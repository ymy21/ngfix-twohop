# HNSW：完成正常一跳后，按 cur/mid 到 bound 的距离选择少量二跳

本次新增独立实验入口，原有 NGFix、无约束二跳、cheap32、DABS 和既有脚本均保留。唯一对公共搜索头文件的修改是包含一个新增实现头；原搜索函数未改写。

## 搜索规则

令 `b` 为当前 beam bound，`s=max(abs(b),1e-6)`。

1. 弹出 cur，完整处理它的正常一跳邻居。按原 beam 规则评分、visited、入队。
2. 暂存这一跳处理过程中被拒绝的 mid。不会把已经接纳的 mid 再拿来做此轮例外探测。
3. 使用一跳完成后的实时 b，仅保留：
   - `(b-d(cur))/s >= cur_margin`（margin=0 时该门禁关闭）；
   - `(d(mid)-b)/s <= mid_gap`。
4. 按 mid 的距离升序选择最多 2 个，距离相同时按原邻接位置打破平局。共用一个 b 时，距离顺序等同于 gap 顺序。
5. 每个 mid 按物理邻接顺序，选择前 8 个未精算、互异的 nn 完整计算 query 距离。此前已经精算的节点跳过，重复 ID 不重复精算。不是随机抽样，也不是先精算所有 nn 再截断；不能声称是到 mid 或 query 最近的 8 个。
6. 这批 nn 按精确距离排序，符合实时 beam 接纳条件的进入正常队列。mid 自身仍保持拒绝。
7. 前一个 probe 可能收紧 b，后一个 probe 开始前重新检查 cur 和 mid 的距离门禁。
8. 每条 query 最多进行 1024 次第二跳完整距离计算；达到后只停止额外二跳，普通 beam 继续。1024 不是总 NDC 上限。

未选中的 nn 不写 visited，后续正常一跳仍可发现它们。此版不计算便宜点积、不调用模型、不持久加边。

这借鉴 ACORN 的有限邻接扩展思路，但不是 ACORN 复现：没有属性过滤，触发条件是 beam 拒绝与距离门禁。按物理邻接顺序选取 nn 可能有顺序偏差，后续可与随机或 cheap 选择对照。

## 阈值依据与三组消融

现有 `result/complete_experiment_report_20261013/tables/probe_feature_bins.csv` 的 HNSW/K10/ef100 分桶中：

| 特征 | 已观察的分桶边界/趋势 | 新实验取值 |
|---|---|---:|
| mid_gap_normalized | 第一四分位桶上界约 0.0266，useful 比例高于更大 gap 的桶 | 最大 0.0266 |
| cur_slack_normalized | 中位分桶边界约 0.0127，更大 slack 的桶总体更有收益 | 最小 0.0127 |

这些是已观察关联和四舍五入分桶边界，不是经过搜索确认的最佳性能阈值。旧统计来自即时二跳，新版在一跳结束后计算门槛，分布会变化；它们是否过严需要本轮结果判断。两个筛选条件也不是独立事件，不能把桶比例直接相乘。

三组都使用相同 mid=2、nn=8、query NN=1024 预算：

| 文件夹 | mid gap 门禁 | cur slack 门禁 | 目的 |
|---|---:|---:|---|
| caps_only | 关闭（用 1e100 的有限大数实现） | 关闭 | 只观察延后选择和数量限制 |
| mid_gap | ≤0.0266 | 关闭 | 加入 mid 门槛 |
| cur_mid | ≤0.0266 | ≥0.0127 | 加入 cur 门槛 |

`control` 另跑普通 beam 与原即时、无约束二跳；新的三个配置也各自重跑相同 beam 曲线以观察计时波动。自动目标召回比较统一使用 control 的 beam，若跳过 control 则使用 caps_only 的 beam。

## 测什么、计时如何做

默认 K=10 和 K=100；各配置 1000 queries，offset=1000，即 query ID 1000–1999。这与本次阈值依据的原始 0–999 分开，便于检验迁移。此前其他开发实验也可能使用过其中部分 query，不能称为从未使用的最终保留测试集。可将 QUERY_OFFSET=2000 用于更晚的独立复核。

性能 ef 沿用已有 `webvid_ngfix_ef_grid.sh`：

- K10：10,15,20,30,40,50,60,70,80,90,100,120,150,180,200,300,400,500,800,1000。
- K100：100,110,120,130,140,150,160,180,200,250,300,400,500,800,1000,2000。
- 为节省时间，原无约束二跳只复测 K10 的 20/100/200、K100 的 100/200/400。它的目标召回比较覆盖不全时，应补 ef，不能据此认定它达不到目标。

默认 CPU=1 是绑定 CPU 编号 1，执行一个查询工作线程。rounds=2。默认 `original` 协议沿用上一轮入口：gettimeofday 包住单次搜索，QPS=查询数/搜索耗时之和；NDC 在搜索中计数，GT/CSV/归因不在计时区间。原普通 baseline 直接调用公开的 `searchKnn`，其漏计的入口 NDC 在计时后加 1，统一报表口径。

等价性检查和统计遍历在测速前独立进行，可能使缓存变热；因此这里保证沿用既有 original 计时边界，而不是宣称完整复现论文所有运行环境。batch 模式另用无统计模板计时；两种模式不能混在同一性能比较中。

新版本默认在全部 1000 queries、每个 ef 上核对诊断实现、带计数 clean 实现和不带计数实现的完整结果及 NDC。测速时无归因 map、事件输出、GT 查询和详细统计计数。算法所需的 nn 预算计数仍保留。

输出：

- `timings.csv`：每轮 recall、mean_ndc、QPS、耗时、校验和、计时协议。
- `timings.csv.queries.csv`：另跑的逐 query recall、NDC，以及新版本的下述计数。
- `timings.csv.latencies.csv`：original 模式下，每轮每条 query 的真实搜索耗时和 NDC。
- `analysis/points.csv`：各配置、ef 的 recall/NDC、两轮 QPS 中位数及范围；original 模式另外汇总延迟均值、P50/P95/P99（两轮样本合并的描述统计）。QPS 中位数不是这些合并延迟均值的严格倒数，每一轮的 QPS 才等于该轮平均延迟的倒数。
- `analysis/target_recall.csv`：达到目标召回的实测点比较；达到的 recall 相差超过 0.001 会标记应加密 ef，不做插值冒充相同 recall。
- `analysis/mechanism.csv`：每 query 的平均计数及 probe 比例。
- `manifest.json`、`commands.txt`、各配置 `benchmark.log`：参数、输入身份、二进制哈希、实际命令和进度。

新计数的定义：

| 字段 | 定义 |
|---|---|
| ndc_entry / ndc_mid / ndc_nn | 入口、一跳、第二跳完整距离次数，三者之和为 ndc |
| rejected_mids | 正常一跳按当时 beam 规则拒绝的 mid 次数 |
| blocked_cur | 在筛选或重新检查时首先未通过 cur slack 条件的 mid 数 |
| blocked_gap | 通过 cur 条件后，未通过 mid gap 条件的 mid 数 |
| blocked_budget | 通过距离门禁后，因 mid/query 预算阻止的 mid 数 |
| blocked_selection | 通过初筛但未被选进本轮最多两个 mid 的数量 |
| probes | 实际进入 mid 邻接探测的次数，可能没有新鲜 nn |
| successful_probes | 至少接纳一个 nn 的 probe 数；不是最终 GT 收益 |
| admitted_nn | 第二跳进入 beam 的候选次数 |
| scanned_nn | clean prefix 内核实际检查的第二跳邻接项数，含 visited/重复项；达到精算限额后不再扫描后缀 |
| expanded | cur 展开次数 |

分阶段阻止原因为互斥的首次阻止原因，满足：`rejected_mids = probes + blocked_cur + blocked_gap + blocked_budget + blocked_selection`。不能把 blocked_cur 与 blocked_gap 当作各自单独启用时的独立通过率。参考诊断版本为 PREFIX 建候选池时可能扫描完整邻接表；本报表的 scanned_nn 来自 clean 内核本身，不能混用参考版本的全池扫描数。

此版没有自动生成 direct/routing recovered GT 的逐事件归因。若需要这层机制，可在少量 ef 上使用现有 `search_hnsw_ngfix --search_mode boundtwohopcmp` 加相同 jump 参数重新诊断；不能把成功接纳率当成最终收益。

如果上面的构建或任何测试失败，先处理失败，不要继续跑性能。纯脚本命令换行不自动阻止后续手工执行，请查看命令状态；正式脚本会遇到错误立即停止。
